# Dials data format

Dials v0.5.1 reads schema 1.2 packages generated by **HJU Phonebook V0.24.1 build69** and remains backward-compatible with schema 1.1.

## File

- Extension: `.dials`
- Encoding: UTF-8 JSON
- Contact records are encrypted and are not stored in plaintext in the outer file.

## Encrypted wrapper

```json
{
  "format": "DialsEncryptedData",
  "formatVersion": 1,
  "kdf": {
    "name": "PBKDF2-HMAC-SHA256",
    "iterations": 310000,
    "salt": "<base64>"
  },
  "cipher": {
    "name": "AES-256-GCM",
    "nonce": "<base64>",
    "ciphertext": "<base64>"
  }
}
```

- PBKDF2 output length: 32 bytes / 256 bits
- AES-GCM nonce: 12 random bytes
- AES-GCM authentication tag is included in the encrypted ciphertext produced by the implementation
- No additional authenticated data is used

## Decrypted payload

```json
{
  "schemaVersion": "1.2",
  "dataVersion": "2026-09-13",
  "generatedAt": "2026-09-13T18:00:00+09:00",
  "period": "2026.09",
  "title": "Organization Phonebook",
  "categories": []
}
```

### Categories

The Windows exporter currently provides three viewer categories:

1. `admin` / `행정부서` — includes administrative and affiliated organizations
2. `academic` / `학과`
3. `facility` / `기타시설`

The order of category organizations and the order of people inside each organization are meaningful. Dials preserves them and does not invent another viewer-specific sort order.

### Organization item

```json
{
  "major": "총무처",
  "minor": "총무팀",
  "people": []
}
```

### Person item

```json
{
  "personKey": "p000001",
  "name": "홍길동",
  "title": "팀장",
  "role": "",
  "job": "팀장",
  "extension": "041-630-1234",
  "mobile": "010-1234-5678",
  "externalNumber": false
}
```


`externalNumber` is an optional boolean introduced in schema 1.2. When `true`, the full phone number remains the callable `tel:` target, but Dials displays `(외부번호)` beside it. If the field is absent, including in schema 1.1 files, Dials treats it as `false`.

`personKey` is an opaque identifier only for the current export. It is not the Windows database `person_id` and is not guaranteed to remain the same in a later export.

Rules:

- The same person across multiple affiliations has the same `personKey` within one `.dials` file.
- Different people with the same name have different `personKey` values.
- Dials groups search results and contact-export candidates by this value.

### Number exposure

The Windows exporter decides which numbers are included.

- Extension: Sheet1 enabled + Sheet1 number visibility
- Mobile: Sheet2 enabled + Sheet2 number visibility
- Records with neither number are omitted from the Dials payload
- Extensions are exported as full numbers such as `041-630-1234`
- Schema 1.2 adds `externalNumber`; this changes the display meaning only and does not replace or shorten the full number
