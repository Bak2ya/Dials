# OurDial data format

This document describes the format currently read by OurDial v0.1.0 and generated by HJU Phonebook V0.8.0 build37.

## Outer encrypted package

`.ourdial` is a UTF-8 JSON file. Contact data is not stored in plaintext.

```json
{
  "format": "OurDialEncryptedData",
  "formatVersion": 1,
  "kdf": {
    "name": "PBKDF2-HMAC-SHA256",
    "iterations": 310000,
    "salt": "<base64>"
  },
  "cipher": {
    "name": "AES-256-GCM",
    "nonce": "<base64>",
    "ciphertext": "<base64>"
  }
}
```

Encryption parameters:

- Password encoding: UTF-8
- KDF: PBKDF2-HMAC-SHA256
- Iterations: 310,000
- Salt: 16 random bytes
- Derived key: 32 bytes / AES-256
- Cipher: AES-GCM
- Nonce: 12 random bytes
- Authentication tag: 128-bit GCM tag appended to the ciphertext by the AES-GCM implementation
- Additional authenticated data: none

## Decrypted payload

Build37 uses schema version `1.0`.

```json
{
  "schemaVersion": "1.0",
  "dataVersion": "2026-09-13",
  "generatedAt": "2026-09-13T16:00:00+09:00",
  "period": "2026.09",
  "title": "Example Organization Phonebook",
  "categories": [
    {
      "id": "admin",
      "label": "행정부서",
      "organizations": [
        {
          "major": "총무처",
          "minor": "총무팀",
          "people": [
            {
              "name": "홍길동",
              "title": "팀장",
              "role": "",
              "job": "팀장",
              "extension": "041-630-1234",
              "mobile": "010-1234-5678"
            }
          ]
        }
      ]
    }
  ]
}
```

The array order is meaningful. OurDial preserves it for organization browsing and for the initial order of people.

## Recommended next schema addition

For reliable person-level grouping, each person record should additionally include an opaque identifier:

```json
{
  "personKey": "p000123",
  "name": "홍길동",
  "title": "팀장",
  "role": "",
  "job": "팀장",
  "extension": "041-630-1234",
  "mobile": "010-1234-5678"
}
```

Requirements for `personKey`:

- It is never displayed to the user.
- It only exists to identify the same person across multiple affiliation records.
- Same person across multiple organizations → same `personKey`.
- Different people with the same name → different `personKey`.
- It should not expose employee numbers or other sensitive internal identifiers.
- A generated opaque ordinal/token is sufficient.

Until this field exists, OurDial v0.1.0 groups records only when both normalized name and mobile number match. Records without a mobile number are kept separate to avoid incorrectly merging same-name people.

## Data that should not be exported

The viewer does not require and should not receive:

- Employee number
- Internal database ID
- Internal notes
- Change logs
- Phone installation location metadata
- Management-only settings
- Passwords or encryption keys
